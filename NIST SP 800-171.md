# NIST SP 800-171 – Security Requirements and Implementation

## 1. Overview

**NIST SP 800-171** is a cybersecurity standard developed by the National Institute of Standards and Technology (NIST).

It establishes security requirements for protecting Controlled Unclassified Information (CUI) when that information is processed, stored or transmitted by nonfederal organizations.

These organizations may include:

- Defense contractors.
- Government subcontractors.
- Engineering and manufacturing companies.
- Technology service providers.
- Organizations handling sensitive government information.

The standard establishes safeguards to protect sensitive information against unauthorized access, disclosure, modification, loss and destruction.

### Purpose

Organizations that handle CUI must implement appropriate security controls to protect the confidentiality of government information.

This involves more than deploying cybersecurity products. Organizations must establish security policies, configure systems, manage access, monitor activities, document procedures and maintain evidence that security requirements are implemented.

### Relationship with CMMC

NIST SP 800-171 is the technical foundation for CMMC Level 2 under the current assessment framework.

| Framework / Document | Purpose |
|---|---|
| NIST SP 800-171 | Defines security requirements for protecting CUI. |
| NIST SP 800-171A | Provides assessment procedures for evaluating security requirements. |
| CMMC | Establishes the DoD cybersecurity assessment and certification framework. |
| System Security Plan (SSP) | Documents the organization's systems and implementation of security requirements. |
| Plan of Action and Milestones (POA&M) | Documents eligible security deficiencies and remediation activities. |

**Revision applicability:** NIST SP 800-171 Revision 2 is the basis for current CMMC Level 2 assessments. Revision 3 was published in May 2024, but organizations must follow the revision required by applicable DoD rules and contracts.

## 2. Controlled Unclassified Information (CUI)

CUI is government information that is not classified but requires protection under applicable laws, regulations or government-wide policies.

Examples may include:

- Military equipment specifications.
- Engineering drawings.
- Defense project documentation.
- Technical information.
- Certain operational information.
- Sensitive government contract information.

### Identifying the CUI environment

Before implementing security controls, an organization must identify where CUI is handled.

This includes determining:

1. Which users access CUI.
2. Which workstations process CUI.
3. Which servers store CUI.
4. Which applications handle CUI.
5. Which networks transmit CUI.
6. Which external services support the environment.
7. Which systems provide security protection to the CUI environment.

### CUI system boundary

The organization must define the systems and components included in its CUI environment.

Example:

```text
                    INTERNET
                       |
                 FIREWALL / VPN
                       |
                 CORPORATE NETWORK
                       |
                 IDENTITY SERVICES
                  AD / ENTRA ID
                       |
                AUTHORIZED USERS
                       |
                ----------------
                |              |
           GENERAL IT      CUI ENVIRONMENT
                               |
                         ENGINEERING SYSTEMS
                               |
                         CUI FILE STORAGE
                               |
                         AUTHORIZED USERS
                               |
                         SECURITY MONITORING
```

The architecture must be adapted to the organization's actual environment. A network segment or VLAN alone does not establish a compliant CUI boundary.

# 4. Security Requirements and Implementation

## 4.1 Access Control (AC)

**Objective:** Ensure that only authorized users, devices and processes can access company systems and CUI.

### Implementation

Organizations should establish:

- Individual user accounts.
- Role-based access control.
- Least-privilege permissions.
- Restricted administrative access.
- Access approval procedures.
- Remote access restrictions.
- Account lockout mechanisms.
- Controls over mobile devices.
- Procedures for disabling accounts.
- Periodic access reviews.

### Technical implementation

**Active Directory**
- Create individual user accounts.
- Organize users into security groups.
- Apply Group Policy.
- Restrict privileged accounts.
- Control access to shared folders.

**Microsoft Entra ID**
- Assign appropriate roles.
- Apply Conditional Access where appropriate.
- Restrict administrative privileges.
- Review group memberships.
- Control external identities.

**Microsoft 365 and SharePoint**
- Restrict access to sensitive document libraries.
- Use security groups to manage permissions.
- Review external sharing.
- Apply appropriate information protection controls.

### Required documentation and evidence

- Access control policy.
- User and administrator account inventory.
- Access approval records.
- Security group membership.
- Permission reports.
- Access review records.
- Account termination procedures.

# 5. Security Documentation and Compliance Management

Technical implementation must be supported by documented procedures and evidence.

Three important components are the System Security Plan, Plan of Action and Milestones, and security assessment evidence.

## 5.1 System Security Plan (SSP)

The SSP describes the organization's information system and how applicable security requirements are implemented.

It should document:

- System boundaries.
- Hardware and software components.
- Systems processing, storing or transmitting CUI.
- Network architecture.
- Security responsibilities.
- Implemented security requirements.
- External system connections.
- Security protection mechanisms.

### Example

An organization uses:

- Microsoft 365.
- Windows Server.
- Active Directory.
- Microsoft Entra ID.
- Microsoft Intune.
- Cisco Meraki.
- VMware.
- Microsoft Defender.

The SSP should describe the relevant systems, their security boundaries, their relationships and how applicable requirements are implemented.

## 5.2 Plan of Action and Milestones (POA&M)

A POA&M documents eligible security deficiencies and the corrective actions required to address them.

It should include:

- Identified deficiency.
- Related security requirement.
- Risk or impact.
- Corrective action.
- Responsible individual or department.
- Target completion date.
- Remediation status.

### Example

| Item | Description |
|---|---|
| Finding | MFA is not enforced for applicable privileged accounts. |
| Security family | Identification and Authentication (IA) |
| Risk | Unauthorized administrative access. |
| Corrective action | Configure and enforce MFA. |
| Responsible department | IT |
| Status | In progress |

POA&M eligibility is restricted. Not all security deficiencies can be deferred to a POA&M, and applicable deadlines must be followed.

## 5.3 Security Evidence

Evidence demonstrates that an organization's security requirements are implemented.

Examples:

- Entra ID configuration exports.
- MFA policy configurations.
- Intune compliance reports.
- BitLocker encryption reports.
- Firewall configurations.
- Security awareness training records.
- Audit logs.
- Vulnerability scan reports.
- Incident response documentation.
- Access review records.

A written policy alone does not demonstrate that a technical control is operating effectively.

# 6. Security Control Assessment

NIST SP 800-171A provides procedures for assessing the implementation of security requirements.

Assessments generally use three methods:

| Method | Description | Example |
|---|---|---|
| Examine | Review documentation, configurations and records. | Review MFA settings and firewall rules. |
| Interview | Discuss procedures with responsible personnel. | Ask an administrator how access is revoked. |
| Test | Verify that security controls operate as intended. | Test whether unauthorized users can access a protected folder. |

### Example: Assessing MFA

An organization claims that MFA is enforced for applicable privileged accounts.

An assessor may:

1. Examine authentication policies.
2. Review privileged account configurations.
3. Interview the IT administrator.
4. Test the authentication process.
5. Review relevant sign-in logs.
6. Document the assessment result.

The organization must demonstrate that the requirement is implemented and operating as intended.

# 7. Continuous Compliance and Security Maintenance

Security compliance is not a one-time activity.

Organizations must maintain their security controls as systems, employees, applications and business requirements change.

### Recommended operational processes

| Process | Frequency / Trigger |
|---|---|
| User access reviews | Periodically and after relevant role changes |
| Privileged account reviews | Periodically |
| Vulnerability assessments | According to the security program |
| Security patching | According to risk and patch management procedures |
| Audit log reviews | According to monitoring requirements |
| Incident response testing | According to the incident response program |
| Security awareness training | According to the training program |
| Configuration reviews | Periodically and after significant changes |
| Risk assessments | Periodically and when significant changes occur |
| Policy reviews | According to the organization's review schedule |

The organization should establish schedules and responsibilities based on its security requirements and risk.

# 8. Implementation Responsibility

NIST SP 800-171 implementation is an organization-wide responsibility.

| Department | Responsibility |
|---|---|
| IT Operations | Implement and maintain technical controls. |
| Cybersecurity | Monitor threats, vulnerabilities and incidents. |
| Management | Approve policies and provide resources. |
| Human Resources | Coordinate personnel security procedures. |
| Compliance / GRC | Maintain documentation and coordinate assessments. |
| Employees | Follow security policies and report suspicious activity. |
| External service providers | Meet applicable contractual and security requirements. |

IT administrators are responsible for many of the technical controls, but they do not independently establish organizational compliance.

# 10. Conclusion

NIST SP 800-171 provides a structured set of cybersecurity requirements for protecting Controlled Unclassified Information in nonfederal organizations.

Effective implementation requires organizations to:

1. Identify and define the CUI environment.
2. Implement the applicable security requirements.
3. Establish organizational security policies and procedures.
4. Maintain secure configurations and access controls.
5. Monitor systems and investigate security incidents.
6. Document implementation and maintain supporting evidence.
7. Assess security controls and address deficiencies.
8. Maintain security protections as the environment changes.

**The objective is to establish a documented, monitored and consistently maintained security environment that protects CUI against unauthorized access, disclosure and compromise.**
